MCP gateway vs MCP server

Um MCP server expõe as tools de um app. Um MCP gateway fica na frente de vários servidores para cada agente conectar uma vez só. Veja quando usar cada um.

Em resumo

MCP gatewayMCP server
O que éUm endpoint na frente de vários servidoresAs tools de um app, como o GitHub
Agentes conectamUma vezUma vez por servidor, por agente
Contexto na conexãoPoucas tools, 1.045 tokens para 125Todo schema, 3.548 só no GitHub
CredenciaisGuardadas uma vez, criptografadasConfiguradas em cada cliente
Revogar um agenteRevoga a chave deleTroca toda credencial
AuditoriaToda chamada num log sóPor servidor, quando existe
Exemplosrunelay, Executor, ComposioMCP do GitHub, Linear, Notion

Como os dois se encaixam

O gateway não substitui servidores MCP, ele é construído em cima deles. Para o seu agente ele é um servidor MCP. Por trás, ele age como cliente de cada servidor, spec OpenAPI ou processo local que você conecta, e guarda as credenciais deles.

No runelay o agente vê search_tools, call_tool e execute para achar e encadear chamadas, mais search_context, read_memory e read_skill para o contexto compartilhado. Os schemas só carregam para as tools que ele usa de fato.

Um MCP server basta quando

  • Você usa um agente e um ou dois apps.
  • O contexto não está apertado. Um servidor soma alguns milhares de tokens e tudo bem.
  • Fazer login de novo não incomoda quando você troca de ferramenta.

Você precisa de um gateway quando

  • Roda vários agentes. Claude Code, Codex e Cursor deveriam ver as mesmas contas.
  • Conecta muitos apps. Onze servidores diretos custam 44.434 tokens na conexão, 42x mais que pelo runelay.
  • Segurança importa. Uma chave por agente, tokens criptografados e um log de auditoria.
  • O contexto precisa viajar. Memória e skills compartilhadas entre todos os agentes.

Perguntas

Um MCP gateway também é um MCP server?

Sim. Ele fala MCP com seus agentes e age como cliente MCP dos servidores que estão atrás dele.

O gateway adiciona latência?

Quase nada. Uma chamada pelo runelay leva 6,6 ms de mediana em localhost, somada ao tempo do próprio servidor de origem.

Um gateway roda servidores MCP locais (stdio)?

Sim. O runelay roda MCP local ao lado de MCP remoto e specs OpenAPI.

Preciso mudar meus agentes?

Não. Aponte para um endpoint, /v1/mcp, cada um com a sua chave. O runelay connect faz isso por você.
