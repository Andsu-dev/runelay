MCP gateway vs MCP server

An MCP server exposes the tools of one app. An MCP gateway sits in front of many servers so every agent connects once. Here is when you need each.

The short version

MCP gatewayMCP server
What it isOne endpoint in front of many serversTools of one app, like GitHub
Agents connectOnceOnce per server, per agent
Context at connectA few tools, 1,045 tokens for 125Every schema, 3,548 for GitHub alone
CredentialsStored once, encryptedSet up in every client
Revoking one agentRevoke its keyRotate every credential
AuditEvery call in one logPer server, if any
Examplesrunelay, Executor, ComposioGitHub, Linear, Notion MCP

How they fit together

A gateway does not replace MCP servers, it is built on them. To your agent it is one MCP server. Behind it, it acts as a client to every upstream server, OpenAPI spec or local process you connect, and keeps their credentials.

In runelay the agent sees search_tools, call_tool and execute to find and chain calls, plus search_context, read_memory and read_skill for shared context. Schemas load only for the tools it actually uses.

One MCP server is enough when

  • You use one agent and one or two apps.
  • Context is not tight. A single server adds a few thousand tokens and that is fine.
  • Logging in again is no big deal when you switch tools.

You need a gateway when

  • You run several agents. Claude Code, Codex and Cursor should see the same accounts.
  • You connect many apps. Eleven servers direct cost 44,434 tokens at connect, 42x more than through runelay.
  • Security matters. One key per agent, encrypted tokens and one audit log.
  • Context should travel. Memory and skills shared across every agent.

Questions

Is an MCP gateway also an MCP server?

Yes. It speaks MCP to your agents and acts as an MCP client to the servers behind it.

Does a gateway add latency?

Barely. A tool call through runelay takes 6.6 ms median on localhost, on top of the upstream server’s own time.

Can a gateway run local stdio MCP servers?

Yes. runelay runs local MCP servers next to remote ones and OpenAPI specs.

Do I have to change my agents?

No. Point them at one endpoint, /v1/mcp, with their own key. runelay connect does it for you.
