The [catalog](/integrations) is a shortcut, not a limit. A custom connector adds anything else: a public MCP server that isn't listed, an internal server on your network or your own API. Once added it works like any other connection: one login, stored encrypted, shared by every agent in the organization.

Open **Connectors** in the panel, add a custom connection and pick the **Connection type**:

| Type | What you give | Use it for |
|---|---|---|
| **Remote MCP** | The server URL | Any MCP server reachable over HTTP |
| **Local command** | A command, arguments and env vars | MCP servers that run as a process, like `npx` packages |
| **OpenAPI** | A spec in JSON or YAML | A REST API with no MCP server |

## Name and tool prefix

The **Name** becomes the tool prefix: a connection named `billing` exposes tools like `billing.list_invoices`. Names are lowercased and anything other than letters and numbers becomes `_`. Agents find the tools with `search_tools` and run them with `call_tool`. You can rename a connection later; the login stays the same.

## Remote MCP

Paste the URL of the MCP server. When you leave the field, runelay probes it and tells you what kind of sign-in it expects:

| Detected | What the panel does |
|---|---|
| OAuth | Shows **OAuth sign-in: the login window opens when you save**. Headers fold behind **Add headers**. |
| Key in a header | Shows **This server asks for a key in a header**. Fill in the headers. |
| No sign-in | Nothing extra. Save and the tools load. |

Detection reads the server's `WWW-Authenticate` challenge and its OAuth protected resource metadata (`/.well-known/oauth-protected-resource`). If it can't tell, nothing is shown and you can still add headers or sign in after saving.

### Headers and API keys

Headers go one per line as `Name: value`, for example `Authorization: Bearer sk-...`. They are stored encrypted with `RUNELAY_SECRET`, and agents never see them: requests made with an API key and the `list_connections` tool show the values as `••••••`.

### OAuth

When the server requires OAuth, runelay runs the flow when you save, stores the tokens encrypted and refreshes them. Most servers support automatic client registration, so there's nothing to set up.

Some services have no automatic client registration (Google is one), so runelay can't create its own OAuth client there. For those:

1. In the service, create an OAuth client with this redirect URL:
   ```
   PUBLIC_URL/v1/oauth/callback
   ```
   The panel shows the exact address under **Use my own OAuth client**. `PUBLIC_URL` must be the public address of your server.
2. In runelay, open **Use my own OAuth client** while adding or editing the connection.
3. Paste the **Client ID** and the **Client secret** (leave it blank if the client has none), then save.

The secret is stored encrypted and is never returned. When editing, a blank secret keeps the current one, and clearing the Client ID removes your client. Changing or removing the client signs the connection out.

## Local command

A command that starts an MCP server on the runelay machine itself (stdio), for example `npx -y @modelcontextprotocol/server-everything`. Add environment variables one per line as `KEY=value`; they are stored encrypted.

<Callout type="warn">
  Local commands are off by default on a server. They need `RUNELAY_ENABLE_STDIO=true`, and even then only an owner or admin can create them from the panel. The process gets a minimal environment, without server secrets. The Docker image ships without Node, so commands like `npx` need the [desktop app](/desktop-app), where local commands are on and use the tools installed on your computer, or a custom image.
</Callout>

## OpenAPI

Point runelay at an OpenAPI spec, in JSON or YAML, by URL (for example `https://api.example.com/openapi.json`). Each operation in the spec becomes a tool.

| Field | Notes |
|---|---|
| **Spec** | The spec URL. |
| **Base URL** | Optional. Without it, the spec's own URL is used. |
| **Headers** | One per line, `Name: value`. Stored encrypted. Use them for the API key. |
| Query parameters | Sent with every request, for APIs that take the key in the query string. Set them as `config.query` through the [REST API](/rest-api) (`POST /v1/sources`). |

## Private network addresses

Outgoing requests to private, loopback, link-local and CGNAT addresses are blocked, to protect cloud metadata and other services on the host. To reach an internal server, set `RUNELAY_ALLOW_PRIVATE_URLS=true` on the runelay server. See [Security](/security#network).

## Status and troubleshooting

Each connection shows its tool count and a status: **Connected**, **Error**, **Needs sign-in** or **Not tested**. After editing, **Save and test** checks it again, and **Test connection** does the same at any time. A connection that needs sign-in can be reconnected from its page or from `/connectors/reconnect`.

If the OAuth window doesn't open or the sign-in never finishes, see [OAuth window not opening](/troubleshooting#oauth-window-not-opening). The most common cause is a `PUBLIC_URL` that doesn't match the address you open the panel at.

## Import from your agents

If the server is already configured in an agent, import it instead of typing it again:

- In the panel, **Import** takes your `~/.claude.json`, `~/.codex/config.toml`, `~/.grok/config.toml` or `~/.cursor/mcp.json`.
- On your computer, `runelay import` turns the MCP servers configured in your agents into connections, and `runelay migrate` brings them along with logins, memories and skills. See [CLI](/cli) and [Migrate](/migrate).

Servers that use headers arrive connected. Importing through the API never expands `${VARS}` from the server environment.
