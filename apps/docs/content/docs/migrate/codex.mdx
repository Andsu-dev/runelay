## What comes along

| | Read from |
|---|---|
| MCP servers | `[mcp_servers.*]` in `~/.codex/config.toml` |
| Logins | `~/.codex/.credentials.json` and, on macOS, the Keychain items under `Codex MCP Credentials` |
| Memories | `~/.codex/memories` |
| Global instructions | `~/.codex/AGENTS.md`, as the pinned memory `instrucoes-globais-codex` |
| Skills | `~/.codex/skills` |

Headers come from `http_headers`. `bearer_token_env_var` and `env_http_headers` are resolved from your shell environment on your computer, so the values are sent, not the variable names.

OAuth accounts Codex already signed in to arrive connected. On macOS the system may ask for permission for each Keychain item; set `RUNELAY_SKIP_KEYCHAIN=1` to skip them.

## What stays behind

- Servers with a `command` (stdio) stay in Codex.
- Servers with `enabled = false` are not imported.
- Accounts without a saved login ask for sign-in in `/connectors/reconnect`.

## Wiring runelay in

If `~/.codex/config.toml` exists, runelay writes (or replaces) its own block:

```toml title="~/.codex/config.toml"
[mcp_servers.runelay]
url = "<url>/v1/mcp"
http_headers = { Authorization = "Bearer rnl_…" }
```

With `--replace`, the migrated `[mcp_servers.*]` blocks are removed from the file. See [Connect agents](/connect-agents/codex).
