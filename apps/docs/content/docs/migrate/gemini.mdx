## What comes along

| | Read from |
|---|---|
| MCP servers | `mcpServers` in `~/.gemini/settings.json` (`url` or `httpUrl`) |
| Global instructions | `~/.gemini/GEMINI.md`, as the pinned memory `instrucoes-globais-gemini` |
| Skills | `~/.gemini/skills` |

Servers that authenticate with headers arrive connected.

## What stays behind

- **Logins.** runelay does not read Gemini's OAuth tokens. OAuth accounts arrive as connections that ask for login in `/connectors/reconnect`.
- Memories: runelay does not read a memory folder from Gemini.
- Servers with a `command` (stdio) stay in Gemini.

## Wiring runelay in

`runelay migrate` and `runelay connect` register runelay in `~/.gemini/settings.json` as `mcpServers.runelay` with `url: <url>/v1/mcp`, `"type": "http"` and the header `Authorization: Bearer rnl_…`. An older `runelay` entry with `httpUrl` is replaced. `runelay pull` writes the brief into `~/.gemini/GEMINI.md`.

With `--replace`, the migrated servers are removed from `settings.json`.
