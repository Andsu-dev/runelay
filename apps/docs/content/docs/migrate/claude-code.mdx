## What comes along

| | Read from |
|---|---|
| MCP servers | `~/.claude.json`: the global `mcpServers` and the `mcpServers` of every project |
| Logins | `~/.claude/.credentials.json` and, on macOS, the Keychain item `Claude Code-credentials` |
| Memories | `memory/` inside every project in `~/.claude/projects`, the current folder's project first |
| Global instructions | `~/.claude/CLAUDE.md`, as the pinned memory `instrucoes-globais-claude-code` |
| Skills | `~/.claude/skills` |

OAuth accounts Claude Code already signed in to arrive connected. On macOS the system may ask for permission before runelay reads the Keychain item; set `RUNELAY_SKIP_KEYCHAIN=1` to skip it.

In each memory folder, `MEMORY.md` is treated as the index, not a memory. Memories it lists under `## Regras de ouro` arrive pinned.

## What stays behind

- Servers with a `command` (stdio) stay in Claude Code.
- Accounts without a saved login ask for sign-in in `/connectors/reconnect`.

## Wiring runelay in

When the `claude` command is on your `PATH`, `runelay migrate` (and `runelay connect`) register runelay at user scope:

```sh
claude mcp add --scope user --transport http runelay <url>/v1/mcp --header "Authorization: Bearer rnl_…"
```

With `--replace`, migrated servers are removed from `~/.claude.json`, both the global list and each project's. See [Connect agents](/connect-agents#claude-code) to do it by hand.
