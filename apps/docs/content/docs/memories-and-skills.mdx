## Memories

A memory is a note your agents share. What one agent learns, all of them know.

- Notes link to each other with `[[slug]]`.
- Every change is versioned.
- Health checks flag memories worth reviewing.
- **Pinned** memories go into every agent's instructions. Only the panel can pin, never an agent.

Agents read memories with `read_memory` and save new facts with `write_memory`. The brief written by `runelay pull` tells them to do so, so memory flows back to runelay instead of local files. When a new slug looks like an existing memory, `write_memory` returns a `similar` list so the agent can update that one instead.

To bring many memories at once, for example from a hosted bot, agents use `import_memory`. See [MCP tools](/mcp-tools#import_memory).

## Skills

Your `SKILL.md` folders, searchable and served on demand. Agents read a skill with `read_skill` and its extra files with `read_skill_file`, and save one with `write_skill` and `write_skill_file`.

The [desktop app](/desktop-app#skill-sync) watches your skill folders and pushes changed skills on its own.

`runelay pull` writes enabled skills you do not have locally to `~/.claude/skills/<slug>/` with a `.runelay` marker. A folder without the marker is yours and is never overwritten.

## Search

`search_context` runs a full-text search across memories and skills. Agents use it before acting on a topic, then open what matters.

## Bring what you have

`runelay push` imports memories, skills and global instructions from Claude Code, Codex, Cursor, Grokbot, Gemini and OpenCode. See [CLI](/cli#push) for the exact folders. `push` never overwrites a memory or skill that is newer on the server.

## Native memory off

If an agent also keeps its own memory, facts split in two places. `runelay connect` and `runelay migrate` turn native memory off in every installed agent that has it, and `runelay doctor` checks it stays off. The [native memory table](/cli#native-memory) lists what changes in each agent.
