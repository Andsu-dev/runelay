The `runelay` CLI runs on your computer, because that is where your agents keep their files. Install it, log in through the browser, done: no env vars, no keys to copy.

## Install

```sh
curl -fsSL runelay.com/cli | sh
```

Or install and set up this computer in one line (recommended):

```sh
curl -fsSL runelay.com/cli | sh && ~/.runelay/bin/runelay setup <your-url>
```

The installer puts the binary in `~/.runelay/bin` and adds it to your shell `PATH` for new terminals. The one-liner calls `~/.runelay/bin/runelay` because the shell you ran it in does not see the new `PATH` yet. Change the folder with `RUNELAY_INSTALL_DIR` and pin a release with `RUNELAY_VERSION=v0.2.0`.

## Commands

Run `runelay` alone in a terminal to open an interactive menu: pick a command with the arrow keys (or `j`/`k`) and press Enter, or choose **setup** to run `login`, `connect`, `migrate`, `pull` and `doctor` in order. Outside a terminal, or with `--json`, it prints the help instead and never draws the banner, colors or animations. `--no-motion`, `NO_COLOR`, `CI` or `RUNELAY_NO_MOTION=1` turn animations off, and `--verbose` adds details to errors.

| Command | What it does |
|---|---|
| `runelay setup [url]` | Sets up this computer in one go: `login`, `connect`, `migrate`, `pull` and `doctor`, in that order. See [Setup](#setup). |
| `runelay migrate` | Brings everything from your agents at once, with accounts already connected. `--yes` skips the confirmation, `--replace` leaves only runelay in the agents. Turns off native memory and archives the imported memory folders into `~/.runelay/archive/<timestamp>/`. |
| `runelay login [url]` | Logs in to the server through the browser and saves this computer's key. |
| `runelay status` | Shows the server, the organization, what is stored in it, the last push, how many agents use runelay and the doctor state. |
| `runelay open` | Opens the web dashboard in the browser. |
| `runelay push` | Sends memories, skills and global instructions from every installed agent. Skips what is newer on the server. |
| `runelay pull` | Writes the brief into `~/.claude/CLAUDE.md`, the `AGENTS.md` of Codex, Grok and OpenCode, and `~/.gemini/GEMINI.md`, and new skills into `~/.claude/skills`. |
| `runelay sync` | `push`, then `pull`. |
| `runelay connect` | Registers the runelay MCP in every installed agent it supports, with one key per agent (see [MCP registration](#mcp-registration)), and turns off native memory in every installed agent that has it (see [Native memory](#native-memory)). |
| `runelay doctor` | Checks that each agent uses runelay for memory and prints a fix command for each problem. |
| `runelay import` | Turns the MCP servers configured in your agents into connections. |
| `runelay logout` | Revokes this computer's key and clears the config. |
| `runelay sponsor` | Opens runelay's GitHub Sponsors page. |
| `runelay help` | Shows the help. |
| `runelay --version` | Prints the CLI version. |

See [Quickstart](/quickstart#what-migrate-brings) for what `migrate` does in detail.

## Setup

`runelay setup` is the recommended path on a new computer. Pass your server's address, or the one the desktop app shows; without it, it finds the server the same way as [`login`](#login).

```sh
runelay setup https://runelay.example.com
```

It runs, in order:

1. `login`: approve a code in the browser. Skipped when this computer is already signed in to that server.
2. `connect`: registers runelay in every agent it finds, one key per agent, and turns off native memory.
3. `migrate`: brings the MCP servers, memories, skills and instructions you already have.
4. `pull`: writes the brief into each agent's instructions file and fetches new skills.
5. `doctor`: checks the result and prints a fix command for each problem.

Each step is the same command you can run on its own later. Restart your agents afterwards so they load the runelay tools.

## Login

`runelay login` looks for `PUBLIC_URL` in `~/runelay/.env` (what the installer writes), then for `http://localhost:4312`, and asks before using what it found. You can also pass the address:

```sh
runelay login https://runelay.example.com
```

The browser shows a code: check it matches the terminal and approve. The key shows up in the panel as `CLI <device>` and is saved in `~/.config/runelay/config.json` (mode `600`, `XDG_CONFIG_HOME` respected).

`runelay open` uses the same server: `RUNELAY_URL` if set, then the saved config, then `http://localhost:4312`. If it cannot open a browser, it prints the URL.

## Push

`runelay push` reads:

| Agent | Skills | Memory and instructions |
|---|---|---|
| Claude Code | `~/.claude/skills` | `~/.claude/projects/*/memory`, `~/.claude/CLAUDE.md` |
| Agents (universal) | `~/.agents/skills` | |
| Codex | `~/.codex/skills` | `~/.codex/memories`, `~/.codex/AGENTS.md` |
| Cursor | `~/.cursor/skills`, `~/.cursor/skills-cursor` | |
| Grokbot | `~/.grok/skills` | `~/.grok/AGENTS.md` |
| Gemini | `~/.gemini/skills` | `~/.gemini/GEMINI.md` |
| OpenCode | `~/.config/opencode/skills` | `~/.config/opencode/AGENTS.md` |

Duplicates are merged (first one wins). Memories listed under `## Regras de ouro` in a `MEMORY.md`, and global instruction files, come in pinned.

`push` never overwrites a memory or skill that is newer on the server, for example one an agent edited with `write_memory` after your last push. It skips those and lists their slugs. Run `runelay pull` to bring the server version down, or edit the local copy and push again.

## MCP registration

`runelay connect` adds a `runelay` server pointing at `<url>/v1/mcp` with `Authorization: Bearer rnl_…` to every agent it finds. It creates one key per agent, named `<Agent> · <computer>` (for example `Claude Code · MacBook`), so you can revoke one agent in the panel without breaking the others. Running it again reuses the keys it already created. It keeps the other servers and keys in each file, writes nothing when the entry is already there, and leaves a file it cannot parse untouched with an error telling you to add the entry by hand. An agent that is not installed is skipped.

| Agent | Found by | File and entry |
|---|---|---|
| Claude Code | `claude` command | `claude mcp add --scope user --transport http` |
| Codex | `~/.codex` | `[mcp_servers.runelay]` with `url` and `http_headers` in `~/.codex/config.toml` |
| Grok | `~/.grok` | `[mcp_servers.runelay]` with `url` and `headers` in `~/.grok/config.toml` |
| Cursor | `~/.cursor` | `mcpServers.runelay` with `url` and `headers` in `~/.cursor/mcp.json` |
| Gemini CLI | `~/.gemini/settings.json` or `gemini` command | `mcpServers.runelay` with `url`, `"type": "http"` and `headers` in `~/.gemini/settings.json`. An older entry with `httpUrl` is replaced. |
| Antigravity | `~/.gemini/antigravity` or `~/.gemini/config` | `mcpServers.runelay` with `serverUrl` and `headers` in `~/.gemini/config/mcp_config.json`, and in `~/.gemini/antigravity/mcp_config.json` when it exists |
| OpenCode | `~/.config/opencode` | `mcp.runelay` with `"type": "remote"`, `url`, `"enabled": true`, `"oauth": false` and `headers` in `opencode.json` (or a plain-JSON `opencode.jsonc`) |
| Kimi Code | `~/.kimi-code` or `kimi` command | `mcpServers.runelay` with `"transport": "http"`, `url` and `headers` in `~/.kimi-code/mcp.json` (`$KIMI_CODE_HOME` is honored) |
| Hermes Agent | `~/.hermes` | `runelay:` with `url` and `headers` under `mcp_servers:` in `~/.hermes/config.yaml` |
| OpenClaw | `~/.openclaw` | `mcp.servers.runelay` with `url`, `"transport": "streamable-http"` and `headers` in `~/.openclaw/openclaw.json` (plain JSON only) |
| MausBot | `~/.openmausbot` | `mcpServers.runelay` with `"type": "http"`, `url` and `headers` in `~/.openmausbot/config.json` |

OpenBot and agentes.chat are hosted, so add runelay in their own settings.

## Native memory

Agents that keep their own memory split your facts in two places. `runelay connect` and `runelay migrate` turn it off in every agent installed on the computer. They keep the rest of each file and print only what changed, so running them again is safe.

| Agent | What runelay sets |
|---|---|
| Claude Code | `autoMemoryEnabled: false` in `~/.claude/settings.json` |
| Codex | `[features] memories = false`, plus `generate_memories = false` and `use_memories = false` under `[memories]`, in `~/.codex/config.toml` |
| Grok | `[memory] enabled = false` and `[memory_v2] enabled = false` in `~/.grok/config.toml` |
| Gemini CLI | `experimental.autoMemory: false`, and `save_memory` added to `tools.exclude` (older versions) in `~/.gemini/settings.json`. Entries already in the list stay. |
| Hermes Agent | `memory_enabled: false` and `user_profile_enabled: false` under `memory:` in `~/.hermes/config.yaml` |
| OpenClaw | `plugins.slots.memory: "none"` in `~/.openclaw/openclaw.json` |
| MausBot | `features.autoRecall: false` in `~/.openmausbot/config.json` |
| Antigravity | Manual. Knowledge Items have no file setting: review or delete them in the Agent Manager. `connect` prints the step and `doctor` shows it as `info`. |
| Cursor | Nothing to do. Memories was removed in Cursor 2.1. |
| OpenCode, Kimi Code | Nothing to do. They have no native memory. |
| OpenBot, agentes.chat | Nothing to do. They are hosted, with no local file to change. |

`migrate` also moves the local memory folders it imported (`~/.claude/projects/*/memory` and `~/.codex/memories`) into `~/.runelay/archive/<timestamp>/`, so nothing is deleted and agents stop reading the old copies. A folder with anything that was not sent stays where it is.

## Doctor

`runelay doctor` checks your computer and prints a fix command next to each problem:

| Check | What it looks for |
|---|---|
| Native memory | Every installed agent in the [native memory table](#native-memory) has memory off. Manual steps show as `info`. |
| MCP registered | Each installed agent in the [MCP registration table](#mcp-registration) has runelay in its MCP config. |
| Conflicting instructions | Lines outside the runelay markers that tell the agent to save memory in `memory/`, `MEMORY.md` or a vault. |
| Leftover local memory | Memory files left in `~/.claude/projects/*/memory` or `~/.codex/memories`. |
| Unpushed skills | Local skills changed after your last `push`. |

```sh
runelay doctor
```

Run it after `connect` or `migrate`, and any time an agent seems to save memory in the wrong place.

## Pull

`runelay pull` only touches the block between `<!-- runelay:start -->` and `<!-- runelay:end -->`. Everything else in your files stays as it is. The brief tells agents to save new facts with `write_memory`, so memory flows back to runelay instead of local files.

Enabled skills you do not have in any agent folder are written to `~/.claude/skills/<slug>/` with a `.runelay` marker. Later pulls update only marked folders and `push` skips them. A folder without the marker is yours and is never overwritten.

## CI and env vars

`RUNELAY_URL` and `RUNELAY_API_KEY` override the saved config, so a pipeline can run `runelay push` with a key created in the panel.

`migrate`, `connect` and `doctor` take `--json`: the human output goes to stderr and stdout gets one JSON object at the end, with each agent (`id`, `name`, `detected`, `mcpSupported`, `mcpRegistered`, `nativeMemory` as `off`, `on`, `manual`, `n/a` or `error`, `message`), the doctor checks (`kind`, `status`, `label`, `details`, `fix`, `paths`) and, for `migrate`, the imported counts, pending logins, archive folder and `keychainPrompts` (how many Keychain items it read). A failure prints `{"ok": false, "error": {...}}`. `migrate --json` implies `--yes`. The [desktop app](/desktop-app#setup-in-two-clicks) uses this to connect agents without a terminal.
